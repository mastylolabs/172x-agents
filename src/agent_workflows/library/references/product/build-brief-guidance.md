# Build brief guidance

Use a brief to create one source of truth for downstream specialists.

- Name source materials and resolve only non-material inconsistencies.
- Separate user direction, source-backed facts, repository observations, assumptions, and open questions.
- State behavior, scope, non-goals, constraints, risks, and observable acceptance criteria.
- Make UX/UI requirements and backend responsibilities compatible without selecting implementation details.
- Escalate material product, compliance, cost, or scope conflicts to the human.
